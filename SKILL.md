# shit-review

Агент закончил и говорит «готово». Дальше идут 4 команды, которые гоняют по очереди. Копируй как есть.

## Активация

Пользователь вызвал `/shit-review` или просит проверить план / бота / сервис после работы агента.

**Не делай проверку «тем же голосом», что писал код.** Запусти **отдельного** ревьюера (см. ниже).

## Модель (обязательно)

Ревьюер должен идти на **самой сильной доступной** модели в текущем раннере (Codex / Claude Code / Cursor / другой).

**Запрещено** ставить на ревью модели семейств **Astra** и **Fable** (и их алиасы/slug с `astra` / `fable` в имени). Если сильнейшая в списке — из запрещённых, возьми следующую по силе разрешённую.

Алгоритм:
1. Выбери самую сильную разрешённую модель, доступную для отдельного агента/задачи.
2. Если выбранная модель не резолвится — **один** retry на следующей по силе разрешённой.
3. В ответе пользователю укажи, на какой модели прошёл ревью.
4. Не подменяй модель без явной просьбы пользователя (кроме запрета Astra/Fable).

## Автозапуск (обязательно)

Запусти **ровно один** независимый проход ревью:

1. Если раннер умеет subagent / Task / отдельный агент — запусти его с логикой из [`agents/shit-review.md`](agents/shit-review.md) (файл рядом с этим `SKILL.md`, в каталоге скилла).
2. Если отдельного агента нет — переключись в роль shit-review **сам**, но без защиты исходной реализации: опирайся только на факты, код, план и запуск.

### Prompt для ревьюера

```text
Full Repository Path: <абсолютный путь к репо или workspace>
Режим: <План | Готовое>
Исходный запрос пользователя: <что просили>
Что сделано (со слов предыдущего агента): <кратко>
Diff: <branch changes | uncommitted changes | natural language>

Ты shit-review. Прочитай agents/shit-review.md из каталога этого скилла и выполни все 4 команды по порядку.
Не защищай чужую работу. Если на шаге 4 не сходится с запросом — почини и покажи заново.
```

**Режим:**
- **План** — есть план/TZ, код ещё не писали или только начали
- **Готовое** — бот, сервис, фича уже реализованы

Если режим неясен — уточни у пользователя одним вопросом, затем запускай ревью.

## 4 команды (для справки; выполняет ревьюер)

1. «Убедись, что это лучшее решение этой задачи. Покажи, какие варианты ты рассмотрел и почему выбрал этот.»
2. «Убедись, что ты подумал на несколько шагов вперёд: что сломается, когда данных станет больше и когда придёт следующая задача поверх этой.»
3. «Убедись, что в коде нет ошибок и он безопасный. Проверь ключи, доступы и данные людей.»
4. «Запусти это и покажи, что работает. Не сходится с тем, что я просил, чини сам и покажи заново.»

**Важно.** Ревьюер = отдельная роль, не тот кто писал. Свою работу он защищает, чужую разбирает честно.

## После ревью

Кратко перескажи вердикт пользователю. Не переписывай весь отчёт — только статус, блокеры, next steps.

Если ревьюер упал на выбранной модели — один retry на следующей разрешённой (не Astra, не Fable). Потом сообщи ошибку.
